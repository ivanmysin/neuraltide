# Следующие изменения NeuralTide

Дата планирования: 2026-11-04.

Этот файл фиксирует приоритеты после завершения P0–P2 и внешнего
аудита. Порядок важен: сначала локальное и обратно совместимое изменение,
затем расширение постановки калибровки, затем отдельный архитектурный этап.

## 1. `fix_first_segment` в multiple shooting

**Цель:** дать пользователю возможность закрепить начальное состояние
первого сегмента за начальным состоянием исходной задачи вместо введения
свободной shooting-переменной `s₀`.

### Предлагаемая семантика

- Добавить в `MultipleShootingProblem` параметр:
  `fix_first_segment: bool = False`.
- При `fix_first_segment=False` поведение остаётся прежним.
- При `fix_first_segment=True`:
  - для сегмента 0 не создаются записи `x0s/0/...`;
  - начальное состояние первого сегмента берётся из базовой задачи;
  - условия сшивки проверяются между концом сегмента `k` и началом
    сегмента `k+1` как раньше;
  - размерность задачи уменьшается на число начальных слотов первого
    сегмента.

### Проверки и тесты

- Один сегмент с `fix_first_segment=True` эквивалентен базовой задаче.
- Несколько сегментов: `size` уменьшается ожидаемо.
- `initialize_from_single_shooting` не создаёт переменные для первого
  сегмента.
- `finalize` по-прежнему проверяет и разрывы, и `loss_ms ≈ loss_single`.
- Старые вызовы без нового параметра не меняют поведение.
- Обновить `docs/api_reference.md`, `docs/optimization.md`, при необходимости
  `AGENTS.md`.

## 2. Свой `x0` для каждого эксперимента

**Цель:** поддержать в `MultiExperimentProblem` отдельные оптимизируемые
начальные состояния для каждого эксперимента, а не только общий `x0`.

### Предлагаемая семантика

- В `ParameterSpace` поддержать имена вида:

  `x0/<experiment>/<population>/<slot>`

- Для совместимости сохранить текущие имена `x0/<population>/<slot>` как
  общий вектор начального состояния, если он задан.
- При материализации начального состояния эксперимента:
  - эксперимент-специфичная запись имеет приоритет;
  - иначе используется общий `x0`;
  - иначе — начальное состояние сети/эксперимента по умолчанию.
- Градиенты по общим динамическим параметрам по-прежнему суммируются по
  экспериментам.
- Градиенты по эксперимент-специфичным `x0` должны идти только через
  соответствующий эксперимент.

### Проверки и тесты

- Два одинаковых эксперимента с общим `x0`: прежнее поведение сохраняется.
- Два одинаковых эксперимента со своими `x0`: градиенты по `x0` не смешиваются.
- `pack`/`unpack`/`bounds_phi`/`value_and_gradient` согласованы по размеру.
- Эксперимент-специфичный `x0` корректно проходит через transforms и bounds.
- FrozenProblem и профили параметров работают с новыми именами.
- Сериализация результатов не ломается.
- Обновить документацию и пример использования.

## 3. Интегрирование связанной сети целиком

**Цель:** устранить архитектурное ограничение В6: сейчас популяции и
синапсы интегрируются раздельно, из-за чего формальный порядок RK4/ROS2 на
связанной сети не достигается.

### Предлагаемая стратегия

Сделать отдельный этап, не смешивая его с двумя предыдущими задачами.

1. **Сохранить текущий split-режим** для обратной совместимости.
2. Добавить режим интегрирования объединённого состояния:
   - плоский вектор состояния сети: состояния популяций + состояния
     синапсов;
   - единая функция правой части, вычисляющая производные всех компонентов
     согласованно;
   - реализация хотя бы для RK4 и ROS2.
3. Для потенциалозависимых синапсов передавать актуальный `v_mean` внутри
   стадий интегратора.
4. Проверить согласованность с:
   - `tf.while_loop` в `NetworkRNN`;
   - BPTT-градиентами;
   - discrete adjoint;
   - float32/float64;
   - существующими интеграторными тестами.
5. Обновить `stiffness_report`, чтобы диагностика могла учитывать полную
   связанную систему, а не только изолированные популяции.
6. Убрать или переформулировать строгий `xfail` для В6 после реализации.

### Проверки и тесты

- Порядок сходимости RK4 на связанной E–I сети со STP становится 4.
- ROS2 сохраняет устойчивость на жёсткой тестовой задаче.
- Split-режим остаётся доступен и даёт прежние результаты.
- Градиенты нового режима проходят FD/Taylor checks.
- Бенчмарк сравнивает split-режим и network-wide режим по точности и времени.

## Пока не трогаем

- **В7** — правило высвобождения в `TsodyksMarkramSynapse` (`u` vs `u⁺`);
  по решению оставлено без изменений.
- Ограничение TF forward-AD после gradient-прогонов в одном `NetworkRNN`;
  сейчас оно документировано и частично смягчено fallback’ами.
- P3-функциональность: Bayesian optimization, SBI/EKI/MCMC/VI,
  mixed-effects, collocation, model discrepancy/UDE, event-aware
  sensitivities и tensor candidate-batch.
- `WilsonCowan.v_mean` как отдельное наблюдаемое: полезный кандидат, но не
  входит в текущий трёхпунктовый план.
