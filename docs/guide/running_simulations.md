# Запуск симуляций

Здесь — как запускать собранную сеть и убедиться, что прогон численно
корректен, прежде чем обучать или калибровать параметры: выбор
интегратора и шага, режимы интегрирования, начальные состояния, контроль
стабильности и особые правила для модели Брюнеля. Сборка сети — в
[Построении сети](building_networks.md).

## Тип данных float64 и воспроизводимость

**Когда использовать.** Любая численно чувствительная работа — калибровка
по данным, жёсткие системы, сравнение прогонов — должна выполняться в
`float64`. Глобальный dtype ставится один раз, **до создания моделей**,
после чего все веса и состояния создаются в выбранном типе.

**Минимальный пример:**

```python
import tensorflow as tf
import neuraltide.config
from neuraltide.utils import seed_everything

neuraltide.config.set_dtype(tf.float64)   # до создания любых моделей
seed_everything(42)                        # seed NumPy и TensorFlow
```

`seed_everything` фиксирует генераторы случайных чисел; учтите, что
абсолютная битовая воспроизводимость между железом и версиями библиотек
не гарантируется — фиксируйте окружение (версии TF/NumPy), если это
важно.

**Типичные ошибки и ограничения:**

- Вызов `set_dtype(tf.float64)` после создания популяций/синапсов не
  конвертирует уже созданные веса — сначала dtype, потом модели.
- В `float32` калибровка возможна, но критерии остановки локальных
  оптимизаторов чувствительны к точности (см. предупреждения в
  [Калибровке](calibration.md#локальные-оптимизаторы-l-bfgs-b-и-least_squares)).
- Для отладки NaN есть флаг `neuraltide.config.set_debug_numerics(True)` —
  он включает `tf.debugging.check_numerics` на ключевых операциях.

## Выбор интегратора

**Когда использовать какой метод.** Все интеграторы — взаимозаменяемые
Kwargs `NetworkRNN(graph, integrator=...)`, модель менять не нужно.

| Интегратор | Порядок/свойства | Когда использовать |
|------------|------------------|--------------------|
| `EulerIntegrator` | 1-й порядок, дёшев | Отладка, грубые прикидки, большие допустимые ошибки |
| `HeunIntegrator` | 2-й порядок | Баланс скорости и точности |
| `RK4Integrator` | 4-й порядок | Основной выбор для точных прогонов |
| `AdaptiveRKIntegrator` | RK 3(2) с PI-контролем субшага | Нестабильная или жёсткая динамика внутри популяции, когда шаг сети не должен меняться |
| `RosenbrockIntegrator` | ROS2, L-устойчивый | Жёсткие задачи, где явные схемы расходятся |
| `IMEXEulerIntegrator` | IMEX по аддитивному разделению | Когда у популяции заданы хуки разделения правой части |
| `ExponentialEulerIntegrator` | Экспоненциальный Эйлер | Почти линейная жёсткая динамика популяции |

Жёсткие методы (всё, кроме Euler/Heun/RK4) делают субшаги **внутри**
одного шага сети по `population.dt`; временна́я сетка `NetworkRNN` при
этом не меняется. В расщеплённом режиме синапсы у них остаются явными.

**Минимальный пример:**

```python
from neuraltide.integrators import (
    RK4Integrator, AdaptiveRKIntegrator, RosenbrockIntegrator,
)

network = NetworkRNN(graph, integrator=RK4Integrator())

# Адаптивный субшаг внутри шага сети:
adaptive = AdaptiveRKIntegrator(rtol=1e-5, atol=1e-7)
# Фиксированный субшаг (сходимость по порядку, отладка):
fixed = AdaptiveRKIntegrator(adapt=False, h0=0.1)

# Жёсткая задача: ROS2 с n_substeps субшагами (h = dt / n_substeps)
ros = NetworkRNN(graph, integrator=RosenbrockIntegrator(n_substeps=4))
```

**Типичные ошибки и ограничения:**

- Ни одна встроенная популяция не задаёт хуки разделения
  (`derivatives_split`/`linear_operator`), поэтому `IMEXEulerIntegrator`
  для них совпадает с явным Эйлером (с предупреждением).
- У IMEX/Rosenbrock/Exponential `local_error` — индикатор отклонения от
  явного Эйлера, а не контролируемая оценка; управление ошибкой — только
  у `AdaptiveRKIntegrator`.
- Аналитический adjoint (`Trainer(grad_method="adjoint")`) с жёсткими
  интеграторами не используйте — для них он не поддержан; градиенты
  берутся BPTT.
- На точном равновесии адаптивный контроллер может разгонять субшаг до
  границы сети — вырожденный случай, не поломка.

Подробная таблица точности/стоимости и сравнение режимов — в
[Интеграторах](../integrators.md).

## Режимы интегрирования: split и network-wide

**Когда использовать какой режим.** По умолчанию `NetworkRNN` шагает
сеть расщеплением (`integration_mode="split"`): сначала синапсы по
пресинаптическим частотам начала шага, затем популяции по замороженному
на шаг синаптическому току. Для изолированной популяции формальный
порядок метода сохраняется, но на связанной сети порядок падает (для
RK4 — до ~2). Режим `integration_mode="network"` отдаёт интегратору
согласованную правую часть всей связанной сети, и RK4 на связанной
TM-сети показывает порядок ~4.

```python
network = NetworkRNN(
    graph,
    integrator=RK4Integrator(),
    integration_mode="network",   # 'split' (по умолчанию) | 'network'
)
```

Режим `'network'` требует `integrator.supports_network_step=True`
(Euler, Heun, RK4, Rosenbrock); у AdaptiveRK/IMEX/Exponential —
`ValueError` в конструкторе.

**Ограничения network-режима:**

- `stability_loss` не оценивается и всегда равен 0 — штраф за
  стабильность работает только в split-режиме;
- аналитический adjoint не поддержан (`NotImplementedError`); BPTT и
  discrete adjoint работают в обоих режимах;
- внешние входы фиксируются на границе шага (zero-order hold), поэтому
  порядок 4 достигается на автономной части и при плавных/константных
  входах; быстро меняющиеся входы ограничивают точность;
- `BrunelFokkerPlanck` в network-режим не переводится (см. ниже).

Сравнительная таблица режимов и рекомендации — в
[Интеграторах](../integrators.md#network-wide-интегрирование-integration_modenetwork).

## Начальные состояния и продолжение прогонов

**Когда использовать.** По умолчанию прогон стартует из нулевого
состояния. Если нужен прогон с конкретного состояния (например, из
конца предыдущего прогона или из заданного распределения напряжений) —
передайте `initial_state` или измените слоты состояния.

**Минимальный пример:**

```python
# Состояние по умолчанию (batch=1)
init_pop, init_syn = network.get_initial_state(batch_size=1)

# Своя инициализация: слоты — это список тензоров [1, n_units] модели;
# смысл слотов определяется конкретной популяцией. Тензоры приводите
# к глобальному dtype (config.get_dtype()).
init_pop[0] = tf.constant([[0.5]], dtype=neuraltide.config.get_dtype())   # например, E для WilsonCowan
init_pop[1] = tf.constant([[0.1]], dtype=neuraltide.config.get_dtype())

out1 = network(t_seq, inputs=inputs, initial_state=(init_pop, init_syn))

# Продолжение: конечное состояние одного прогона — начальное для другого
out2 = network(t_seq, inputs=inputs, initial_state=out1.final_state)
```

`final_state` — кортеж `(pop_states, syn_states)` той же структуры,
что и `get_initial_state()`, поэтому цепочки прогонов стыкуются без
потерь.

**Типичные ошибки и ограничения:**

- Структура слотов зависит от модели (у `IzhikevichMeanField` — `[r, v,
  w]`, у `BrunelFokkerPlanck` — `[P, p_r, nu_buf]`); меняйте слоты,
  только понимая их смысл, иначе получите нефизичный старт.
- Синаптическое состояние тоже входит в начальное состояние — при
  «горячем» старте из середины эксперимента учитывайте и его.
- Пакетная размерность больше 1 в текущем последовательном прогоне не
  поддержана — ведущая ось батча всегда 1.

## Штраф за нестабильность: stability_penalty_weight

**Когда использовать.** В split-режиме интеграторы RK4/Heun возвращают
оценку локальной ошибки шага; `NetworkRNN` аккумулирует её в
`output.stability_loss`. Ненулевой `stability_penalty_weight` добавляет
эту величину к целевой функции при обучении — мягкий барьер против
развала интегрирования в нефизичной области параметров.

```python
network = NetworkRNN(
    graph,
    integrator=RK4Integrator(),
    stability_penalty_weight=1e-3,
)
output = network(t_seq, inputs=inputs)
print(output.stability_loss)   # 0 или малое при устойчивом шаге
```

**Типичные ошибки и ограничения:**

- В network-режиме `stability_loss` всегда 0 — штраф там не работает
  (не несёт информации о стабильности).
- Большой рост `stability_loss` в прогоне — сигнал уменьшить `dt` или
  взять более устойчивый интегратор, а не просто увеличивать вес штрафа.
- Во время чистой симуляции (без обучения) достаточно мониторить
  значение, не включая штраф.

## BrunelFokkerPlanck

**Когда использовать.** Популяция ЛИФ-нейронов в приближении
Фоккера–Планка (Brunel 2000, модель A): дрейф-диффузия на сетке
напряжений с поглощающим порогом, реинжекцией `ν(t − τ_rp)` в
`v_reset` и рефрактерной массой. Связь с сетью — `μ = mu_0 + I_syn`,
параметр `sigma_ext` задаёт диффузию.

**Минимальный пример (автономная проверка):**

```python
from neuraltide.populations import BrunelFokkerPlanck
from neuraltide.integrators import EulerIntegrator

pop = BrunelFokkerPlanck(
    dt=0.5,
    params={
        "tau_m": 20.0, "v_theta": 20.0, "v_reset": 10.0,
        "tau_rp": 2.0, "mu_0": 18.0, "sigma_ext": 3.0,
    },
    grid_size=250,
    v_min=-80.0,
)
state = pop.get_initial_state()
zero = tf.zeros([1, 1], dtype=tf.float64)
syn = {"I_syn": zero, "g_syn": zero}
for _ in range(2000):
    state, _ = EulerIntegrator().step(pop, state, syn)
rate = pop.get_firing_rate(state)
mass = tf.reduce_sum(state[0]) * pop.dV + state[1]   # ∫P dV + p_r
```

**Типичные ошибки и ограничения:**

- Используйте `EulerIntegrator` или `HeunIntegrator`: буфер задержки
  `ν(t − τ_rp)` точен для Эйлера. Остальные схемы для этой модели не
  предназначены; network-wide режим для неё не поддержан.
- Внутри `derivatives()` есть CFL-субшагинг по сетке напряжений —
  не пытайтесь «помочь» модели, уменьшая `dt` сети без нужды; оцените
  сначала `stiffness_report`.
- Контроль качества: полная вероятность `∫P dV + p_r` должна сохраняться
  (~1), стационарная частота — совпадать с аналитикой Брюнеля
  (уравнение (21) статьи; около порога — с точностью ~0.2% при
  `grid_size=250`). Готовый сценарий сравнения — в
  `examples/example_06_brunel_fp.py`.
- В калибровке метод сквозного перебора сегментов (multiple shooting)
  для этой модели не поддержан.

## Как проверить корректность прогона до обучения

**Когда использовать.** Обязательно перед любой калибровкой или
обучением — и после любого существенного изменения модели, шага `dt`
или протокола.

Прежде чем тратить бюджет на оптимизацию, убедитесь, что прямой прогон
численно корректен. Минимальный набор проверок:

**1. Прокон не развалился.** Классификация результата и NaN-контроль:

```python
from neuraltide.integrators import classify_failure

output = network(t_seq, inputs=inputs)
status = classify_failure(output)
print(status)   # {'status': 'ok' | 'nan' | 'diverged', 'max_abs': float}
```

**2. Шаг устойчив.** Диагностика жёсткости даёт предельный шаг для
явного интегратора. Для сети с объявленными входами передавайте
`CalibrationProblem` (он несёт протокол: временную сетку и входы) —
голый `NetworkRNN` принимается, только если входов нет:

```python
from neuraltide.integrators import stiffness_report

report = stiffness_report(problem, scope="populations")  # или scope="network"
print(report["stiffness_ratio"], report["explicit_dt_limit"], report["euler_stable"])
```

`explicit_dt_limit` — максимальный шаг, при котором Эйлер устойчив по
спектру; `scope="network"` учитывает и синаптическую связность. Если
ваш `dt` близок к лимиту — уменьшите шаг или возьмите устойчивый метод
(RK4, ROS2).

**3. Сходимость по шагу.** Перезапустите ту же конфигурацию с `dt/2`
(и `dt/4`) и сравните firing rates/потерю: при сходимости различия
должны падать с порядком метода. Для задачи калибровки есть готовый
инструмент `dt_convergence` (см.
[Верификацию в Калибровке](calibration.md#верификация-задачи-до-оптимизации)).

**4. Стабильность интегрирования.** Мониторьте `output.stability_loss`
при обучаемых сценариях: рост на протяжении эпохи — признак
недостаточно малого `dt`.

**5. Специфика моделей.** Для `BrunelFokkerPlanck` — сохранение нормы
и совпадение стационарной частоты с аналитикой (см. выше).

**Типичные ошибки и ограничения:**

- Проверки 1–2 не заменяют сходимость по шагу: устойчивый шаг может быть
  всё ещё слишком грубым для нужной точности.
- `stiffness_report` замораживает внешние входы (zero-order hold) —
  быстрые входные сигналы оценка не видит.
- `stiffness_report` по сети с объявленными входами требует
  `CalibrationProblem` (протокол), а не голый `NetworkRNN` — иначе
  `ValueError`.
- Если прогон разваливается только при некоторых параметрах — сузьте
  границы `min`/`max` в params и повторите диагностику.
